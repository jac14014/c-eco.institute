# Review SIL 19×19 security boundaries

## Inputs

The current system architecture, data-flow diagram, access-control design, source revision or deployment scope, test environment and applicable data classifications. If only a concept dossier exists, produce a threat model and evidence gaps; do not claim that a code audit occurred.

## Prompt

Review SIL 19×19 as one global platform used by Living Labs and administered operationally by GIH. Define the exact version and environments under review. Map assets and trust boundaries: Fellow intake, local evidence, domain analysis, scientific validation, GIH integration, dashboards, model registry, threshold alerts and any financial interface.

Assess authentication and role permissions across L0–L3 and GIH; segregation of project and jurisdictional data; source provenance and immutable version history; prompt or document injection into AI workflows; secrets and dependency exposure; audit logs; backup and recovery; incident response; and approval checks before any external alert or financial action.

For each finding, show the input route, affected asset, evidence from the exact reviewed version, conditions needed for exploitation, impact, severity, a bounded remedy and a verification step. Use synthetic data and a test environment for dynamic checks. Report tests you could not run and residual risk. Never equate a clean automated scan with proof of security.
